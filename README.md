
# 三体运动模拟器 · Three-Body Problem

> 「宇宙就是一座黑暗森林。」——《三体》
> 这里不讲故事，只把万有引力定律原封不动地交给 GPU。

基于 **three.js** 的三体运动 3D 实时模拟器。三个天体在牛顿引力下互相拉扯，轨道实时积分、实时绘制，
并配备守恒诊断、混沌敏感性对照与九组经典初始构型；另有一个按真实周期运行的**太阳系模式**（八大行星 + 月球）。

---

## 快速开始

```bash
npm install          # 安装依赖（仅 three + vite）
npm run dev          # 开发模式，自动打开 http://localhost:5173
npm run build        # 构建到 dist/
npm run standalone   # 构建 + 额外产出 standalone.html（单文件版）
```

**单文件版 `standalone.html`（约 0.58 MB）**：双击即可用浏览器打开，无需服务器、无需联网，
所有 JS/CSS 都已内联。适合分享与离线演示。

物理内核自检（不依赖浏览器）：

```bash
node scripts/verify-physics.mjs
```

## 两种宇宙模式

控制台顶部随时切换，两种模式各自独立取景，互不干扰。

### 三体问题模式
三颗恒星在互引力下运动，九组初始构型可用（`1`–`9` 快捷键直达）。
**切换构型会完整回到该构型的默认态**：物理回到 t=0 的初始条件、拖尾清空、软化因子与倍率按该构型重设、
相机归位、聚焦与信息卡一并清除——不会因为上一构型跑飞了而「继承」残留视角。

### 八大行星模式 · Solar System
太阳居中（自发光球体 + 点光源 + 辉光精灵），水星 → 海王星按**真实公转周期**绕日运行
（`岁月 years` 由实时累积，周期比与远近次序严格遵循真实数据）。轨道半径做了幂压缩 `r = 2 + 9.5·a^0.42`
以便八大行星同框；轨道倾角也按真实值施加到各自的轨道平面上。土星带环，木星最庞大。

**地球带着月球同行**：月球挂在地球轨道组内部，自动继承地球的公转；
周期取真实恒星月 27.32 天，**潮汐锁定**（自转 = 公转，永远同一面朝向地球）。
真实地月距离只有 0.0026 AU，在显示尺度下连一个像素都不到，因此绕地轨道半径做了艺术放大——
但周期、倾角、相对大小仍严格取值。**点击任意天体**（含月球）即可聚焦并查看资料。

## 功能

### 物理内核
- **Velocity Verlet 辛式积分**：二阶精度、时间可逆、长期能量不漂移。
  相比 RK4，辛式积分器把能量误差限制在 bounded oscillation 而非单向累积——这是「恒纪元」能撑多久的关键。
- **自适应步长**：由最近距离 `d_eff`、最大速度 `v_max`、最大加速度 `a_max` 共同约束，
  且**在子步循环内部每 16 步重估一次**（否则时间倍率拉高时，帧中途突发的近距离飞越会被整个错过）。
- **主动降速保护**：当所需子步数超过上限时，宁可让模拟时间变慢，也不放大步长硬闯。
  HUD 会显示 `⚠ 近距飞越降速 ×0.67`。
- **Plummer 软化引力** `a = G·Σ m_j·\vec{r}_{ij} / (r² + ε²)^{3/2}`，ε 可调；
  势能用与之严格对应的 `U = −G·m_i·m_j / √(r²+ε²)`，保证能量守恒判定自洽。

### 交互与视觉
- **视角**：左键旋转 / 滚轮缩放 / 右键平移；四个预设机位（默认 / 俯视 / 侧视 / 斜角）；切换构型自动取景。
- **点击聚焦**：射线拾取天体 → 相机 0.95s 平滑补间 → 之后随该天体平移，信息卡实时刷新。
  三体显示质量 / 位置 / 速度 / 速率；行星显示位置 / 角速度 / 轨道半径；月球额外显示地月距离与轨道相位。
- **实时调参**：三个天体的质量、位置、初速度全部可拖动滑块即时改写（质量用对数滑块，覆盖 1e-3 ~ 1e4）。
- **时间**：暂停 / 单步 / 0.05× ~ 8× 变速 / 重置。
- **轨道拖尾**：定长环形缓冲 + 自定义着色器实现「越旧越淡、越旧越暗」的彗尾；长度与亮度可调。
- **视觉**：UnrealBloom 泛光、程序化生成的星云穹顶与 5200 颗星、参考网格、质心标记。
- **目标帧率**：无限 / 90 / 60 / 30 四档**渲染节流**（物理与逻辑仍按真实时间每帧推进）。
  HUD 显示的是**真实渲染帧率**并附「目标 N」徽章；受屏幕刷新率上限约束时如实显示实际值（如 60Hz 屏上目标 90 只会跑到约 60）。

### 沉浸观赏 + 程序化宇宙音景
- **沉浸模式**（`I`）：隐藏全部 UI，仅余宇宙，相机缓慢自转；移动鼠标唤醒右上控制簇，2.6s 闲置淡出；`Esc` 退出。
- **背景音乐**（`M`）：全部由 Web Audio API **实时合成**，零外部音频文件，因此单文件版同样可用。
  5 首生成式和弦音景——寂灭 / 远星 / 流浪 / 广寒 / 熵——低频铺底 + 稀疏五声钟铃 + 长卷积混响，无缝循环。
  首次点击或按键会自动起乐（浏览器自动播放策略要求在用户手势内创建 AudioContext）。

## 默认参数（单一真源）

所有默认值集中在 `src/core/constants.js`，**控制台滑块的初值一律从这里读取**，
不允许在 UI 层另写死一个数字——否则就会出现「面板显示 0.85、实际生效 0.15」这类显示与生效分家的 bug。

| 参数 | 默认值 | 常量 |
|---|---|---|
| 引力软化 ε | 0.02（周期解构型载入时自动置 0） | `PHYSICS_DEFAULTS.softening` |
| 积分精度 η | 1e-4（速度）/ 5e-4（加速度） | `etaVelocity` / `etaAcceleration` |
| 步长下限 / 上限 | 1e-11 / 2e-2 | `dtMin` / `dtMax` |
| 单帧最大子步 | 50000 | `maxSubsteps` |
| 初始扰动（幽灵宇宙） | 1e-9 | `PHYSICS_DEFAULTS.perturbation` |
| 拖尾长度 / 亮度 | 2400 点 / 0.95 | `RENDER_DEFAULTS.trailCapacity` / `trailOpacity` |
| 辉光强度 | 0.15 | `RENDER_DEFAULTS.bloomStrength` |
| 时间倍率 | 1.0× | `TIME_DEFAULTS.timeScale` |
| 目标帧率 | 无限 | 控制台「目标帧率」 |
| 音量 / 默认音轨 | 0.45 / 寂灭 void | `AUDIO_DEFAULTS.volume` / `track` |

## 物理正确性自检

```bash
node scripts/verify-physics.mjs
```

当前 **25 / 25 全部通过**：

| 检验项 | 结果 |
|---|---|
| 八字形轨道 · 一周期后位置闭合 | 误差 1.7e-8 |
| 八字形 · 100 个周期后能量漂移 | 5.6e-7 % |
| 八字形 · 总动量 / 质心漂移 | \|P\| = 4.8e-14，\|R_com\| = 2.9e-11 |
| 拉格朗日三角 · 一周期闭合 / 半径恒定 | 误差 1.1e-7 / 1.000000 → 1.000000 |
| 蝴蝶 / 熊蜂 / 飞蛾 / 阴阳 / 护目镜 · 周期闭合 | 2.0e-4 ~ 9.7e-4 |
| 上述五者 · t=60 能量漂移 | 6.1e-7 % ~ 3.3e-4 % |
| 二体退化 · 10 圈后半径 | 0.50000000（期望 0.5） |
| 日·地·月 · t=30 能量守恒 / 卫星未被甩飞 | 7.3e-12 % / 间距 0.416 < 希尔半径 1.39 |
| 时间可逆性 · 速度取反往返 t=5 | 回到初始位置误差 5.2e-10 |

> 注：Šuvakov–Dmitrašinović 族（蝴蝶、熊蜂等）是「近碰撞」自由落体轨道，最近距离可达 1e-2，
> 且文献初值只给到 5 位小数，因此闭合误差存在约 1e-3 的固有下界——再收紧步长也不会更小。
> 这也是为什么它们的默认软化因子取 ε = 0（软化会改变有效引力，反而破坏周期闭合）。

## 单位制

无量纲化：G = 1，质量量级 1，距离量级 1。
这样八字形轨道等文献初始条件可以照搬数值，无需换算。
面板显示的「模拟时间 t」即该单位制下的时间。

太阳系模式不在此列：它按各自的真实公转周期（年）运行，轨道半径与天体半径仅为观赏做过压缩，
唯一被艺术放大的是月球的绕地轨道半径（真实值在本图尺度下不可见）。

## 已知边界

- 三体系统本质混沌：除拉格朗日三角形等少数稳定构型外，长时间运行后轨迹必然发散，
  这是物理真实而非数值错误。守恒诊断面板可以用来区分「物理发散」与「数值失真」。
- 若用户把 ε 设为 0 又构造出真正的碰撞初值，积分器会触发降速保护（画面变慢而非崩坏），
  但极深碰撞仍可能把某个天体高速甩出——这是牛顿引力的真实行为。
- 目标帧率受显示器刷新率上限约束：60Hz 屏幕上「目标 90」实际只能跑到约 60，
  HUD 显示实际渲染帧率而非目标值，这是刻意为之——宁可如实呈现，也不虚报。
